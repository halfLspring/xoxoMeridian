# feat-091：Blog 空间草稿编辑与发布开发计划

日期：2026-09-30。状态：D1—D12 已实施；2026-09-30 用户反馈的重复蒙版及边框控件未随动已修复，标准门禁与生产浏览器回归通过；实施和验证记录见 [feat-091 验收证据](../../feature_list.json)。下方契约已按 feat-095 工具栏精简、feat-096 入口恢复和 feat-097 整稿平移要求同步修订，第 2、15 节为实施前的事实与规划交付记录。

目标：Blog 保留两条创建路径。**New Post → 独立博文表单 → 发布文章** 沿用原有发文行为；**右键“新增草稿” → 框选 → 编辑图文与连线 → 发布整组作品** 提供空间创作。空间内容在发布前只属于当前账号，发布后以一个作品条目进入时间线。

需求来源为用户提供的截图、文字说明及 12 轮 `steelman-deliberation`。完整选择及论证保存在 [feat-091 验收证据](../../feature_list.json)。截图是根目录用户原有 PNG，仅作视觉参考，不移动、删除或作为正式产品资产提交。

2026-09-30 最新要求（[feat-095 验收证据](../../feature_list.json)）：移除“内容列表”“放大查看”“调整边框”及其专属功能，删除整组公开提示文案；博文/图片/连线工具栏贴齐边框底部。此要求覆盖 D11 的独立放大入口及原计划的目录、数值边框设置、自动扩展功能，八向手柄和初始等比适配继续保留。

2026-10-01 入口恢复（[feat-096 验收证据](../../feature_list.json)）：顶部恢复 New Post 及 /posts/new 原独立发文流程，新建草稿只保留右键菜单入口；My Draft 仅管理已有草稿。同日用户启动 [feat-097](../../feature_list.json)，增加本人私密草稿从边框平移整组的能力，覆盖原“不提供整组拖动”的约定；公开作品仍按时间线定位。

## 1. 已确认决策与范围

| 决策 | 用户选择 | 本期契约 |

| D1 | B | 发布后保留整组归属和内部排版，作为一组作品管理 |
| D2 | A | 框选创建空白草稿；框内已有公开内容不复制、不吸收、不改变归属或可见性 |
| D3 | B | 边框是裁切窗口；缩小只裁切显示，保留元素尺寸、坐标、数据，扩大恢复 |
| D4 | A | 整组按首次发布时间进入时间线；创建时的页面框选位置只用于编辑 |
| D5 | A | 已发布作品直接修改，保存后更新公开内容；不建立私密修改稿，首次发布时间不变 |
| D6 | B | 公开作品的正文与边框仅作者管理；图片、连线可由其他已登录用户增删改；草稿仅创建者访问 |
| D7 | C | 草稿可连接外部公开博文/图片；线在发布前私密，随作品发布公开，不改变外部内容归属 |

| D11 | A（后续修订） | 窄屏默认等比缩小呈现全貌，不改持久化坐标与裁切窗口；feat-095 移除独立放大入口，博文仍可点击卡片进入正文面板 |

原始要求中已明确的入口：页面右键菜单在“添加图片”下增加“新增草稿”，进入可继续调整大小的框选流程。

以下章节中的组件、数据字段、默认尺寸、冲突处理和兼容方式，是结合这些决策及现有代码选定的实施约定，不冒充用户逐项口头选择。当前没有阻塞计划落盘的待决策问题。

边界：

- “公开”沿用现有 Blog 的登录边界，指所有已登录用户；不新增匿名网站或公开下载入口。Agent log 继续执行原房间成员权限。
- D10 不改变现有 Session 策略；同账号多标签页可操作不同草稿，跨设备恢复仍需有效登录，不承诺同时维持多个有效设备会话。
- 裁切是展示方式，不是另一种权限。整组发布包含所有所属元素，包括被裁切的部分；正文详情与合法 API 读取也按整组状态授权。feat-095 仅移除发布区的解释文案，整组发布的语义不变。
- 不新增博文自由拖动/旋转、博文与博文连接、复制旧内容入稿、作品拆分/合并、发布后撤回为私密、版本分支或离线同步。
- 不恢复已退役的 Atlas 页面/SSE，不改 Agent 工具或 Runtime，不顺带整治无关历史质量问题。

## 2. 实施前代码依据与设计选择

| 现有事实 | 对实施的要求 |
| --- | --- |
| [Post/Atlas 模型](../../prisma/schema.prisma)没有草稿/作品关系，Post.publishedAt 非空 | 增加作品实体和明确关联，不能用几何框选推断成员或用前端标记模拟隐私 |
| [PostEditor](../../components/blog/PostEditor.tsx)、[Action](../../app/actions/posts.ts)提交即发布 | 拆出可复用文字表单，新草稿允许未完成内容自动保存，发布再执行完整校验 |
| [Post 可见性](../../lib/post-visibility.ts)允许所有 user_post | 公共文章查询必须排除未发布作品；草稿查询单独校验 owner |
| [Home 访问条件](../../lib/home-board.ts)的照片分支只限 board/type，允许共享操作 | 新作品内容必须按作品权限读写；旧共享入口不能成为绕过作品状态的写入路径 |
| [图片读取](../../app/api/atlas/uploads/%5Bfilename%5D/route.ts)仅查登录，长时间 private 缓存 | 校验数据库资源归属后才读取字节，统一禁止身份相关缓存复用 |
| [HomeTimelineBoard](../../components/home/HomeTimelineBoard.tsx)使用全局照片层，博文靠 DOM 排列 | 分离作品内部坐标、时间线位置、屏幕视图；草稿和公开作品共用渲染器 |
| [排序](../../lib/post-timeline.ts)/[游标](../../lib/post-pagination.ts)以 publishedAt+id 稳定分页 | 新混合时间线独立定义带条目类型的游标；组内文章不再重复插入 Blog 时间线 |
| [Atlas 旧入口](../../lib/atlas-board.ts)限定 atlas-global-board，Home 限定 home-board | 保留两类 board 隔离；旧 Atlas API 仍存在，必须测试不能碰到作品内容 |
| [存储适配层](../../lib/storage/atlas-storage.ts)支持 local/OSS，delete 当前吞掉错误 | 草稿上传需要可追踪清理记录；新清理路径必须区分“已不存在”和真实失败 |
| [工具注册表](../../agent/tool-registry.ts)没有画布编辑工具 | 按 D12 不实现截图中的 Agent 按钮或伪造调整动画 |

采用 **BlogWork + 现有 Post/AtlasElement/AtlasConnection 显式归属**。避免另存一套发布副本：草稿与公开作品沿用同一组 ID 和内容，只在首次发布事务中改变作品状态、分配正式文章 slug 和发布时间。这样跨作品端点、文章详情和发布后协作有稳定身份。

Post 的 Markdown、作者信息、slug 唯一性，照片的拖动/缩放/旋转及存储适配层继续复用；业务授权与生命周期下沉到 `lib/blog-work/`，不堆入 Route Handler。

## 3. 页面入口和完整用户流程

### 3.1 创建、取消与打开

1. 空白处右键菜单依次显示“添加图片”“新增草稿”。菜单继续 portal 到 document.body，用视口坐标定位并避让边缘，保留 feat-090 的定位修复。
2. 点击“新增草稿”进入框选模式；主指针拖出矩形，反向拖动也归一化为正确范围，松手后创建草稿。Escape、pointercancel 或丢失捕获取消当前框选，不创建数据库记录。2026-09-30 feat-093 起不再显示常驻操作说明卡片：卡片默认完全透明且不接受指针事件，只在键盘聚焦或创建失败时显现，原文“显示操作说明”作废。
3. 只有框选完成且创建请求成功才进入正式编辑。请求失败保留矩形和“重试创建”（feat-093 起该按钮随恢复卡片一起显现）；以同一个 mutationId 重试，不能生成重复草稿。
4. 顶栏保留 New Post 与 My Draft；New Post 链接 /posts/new，My Draft 管理已有空间草稿。创建空间草稿只通过 Blog 的右键“新增草稿”，不再显示 New Draft 按钮；旧 `/home?draft=new` 不再触发框选。
5. 进入框选模式后，键盘可聚焦并激活“使用默认区域”，生成建议 960×540 的编辑范围，之后通过八向手柄或手柄方向键调整。My Draft 保留已有草稿的键盘选择与管理；空间草稿创建统一由右键菜单进入。
6. `/posts/new` 恢复经认证的独立 PostEditor，完整填写标题与正文后显式发布独立文章，进入原文章详情；打开表单不创建文章或 BlogWork。打开已有稿使用 `/home?draft=<workId>`，服务端验证后加载；他人草稿与不存在的 ID 使用同样的不可用反馈。

### 3.2 蒙版与编辑范围

- 视觉沿用参考图的绿色透明填充、虚线边框、八个调整手柄、左上 DRAFT/锁图标/仅自己可见、右上保存状态/退出草稿/发布。底部工具栏仅有博文、图片、连线，距边框底部 8px 水平居中，不再有次级按钮或公开提示占位。
- 2026-09-30 边框反馈修正：透明填充、虚线与八个手柄只绘制在同一个裁切窗口；顶部状态区和底部工具区跟随窗口原点及尺寸，不能由固定初始大小的第二层容器定位。控件不参与窗口尺寸计算；窗口过小时，保持按钮正常尺寸并将操作区紧贴窗口下方，超宽窗口则把操作区限制在窗口的屏幕可见部分。上述适配不改内部内容坐标、裁切范围或当前显示比例。
- 草稿是独立图层，只有显式创建到当前作品的元素才属于草稿。覆盖的旧公开内容仍按原规则展示；默认不把点击穿透成旧内容的编辑操作。连外部内容时进入明确的端点选择模式。
- 一次仅挂载一份可编辑草稿，背景时间线可滚动查看。私密草稿的坐标与尺寸随作品保存，不写入其它用户的页面状态。
- 框选后的边框保留八向缩放手柄；左边/上边调整改变裁切窗口原点，不能把子元素跟着平移。feat-097 增加四条边的整稿平移命中区，缩放手柄优先命中；正文、图片、状态/发布区和工具栏继续执行各自操作，不从内容区起手平移。
- 整稿平移只适用于本人未发布草稿：内容、蒙版和操作区一起移动，鼠标显示 grab/grabbing；只写入页面放置点 draftX/draftY，不修改内部坐标、尺寸、旋转、裁切窗口或公开排序。拖动按页面像素计算，窄屏等比显示不对整稿位移做比例逆变换；缩放手柄仍按内部坐标逆变换。适配宽度由固定宿主决定，平移不触发内容缩放或控件换行。
- 四边平移区支持 Tab 聚焦、方向键每次 1 页面像素、Shift 加方向键每次 10 页面像素。拖动期间仅预览，松手经既有版本/幂等队列自动保存；Escape、pointercancel 或丢失捕获取消当前预览，保留之前已提交但尚待确认的位置。连续手势不被前次迟到响应覆盖；失败保留本地位置并允许使用原幂等键重试，未确认写入不能发布。
- 键盘手柄提供精确操作；最小 160×120，最大 8192×8192 个逻辑像素，前后端共用此窗口校验。上限约束持久化裁切窗口，不约束作品内部场景的总跨度，也不保证 300 个元素可同时装入一个窗口；内容仍可保留在窗口之外。不得用减少已允许的元素数量、缩放或重排内容来满足窗口上限。
- 内容只裁切、不删除；作者通过八向手柄改变窗口即可恢复相应区域的可见内容。保留既有博文深链及正文面板，不再提供内容目录、图片详情/数值设置、独立缩放或自动扩展到全部内容；不能承诺一个窗口可展示全量内容。

### 3.3 博文、图片与连线

- “博文”新增一个空白文章编辑块，标题和 Markdown 正文可边写边自动保存；关闭文字面板返回画布。正文有独立可查询 label，草稿中的单篇文章没有单独“发布”按钮。
- 组内博文按添加顺序形成稳定的纵向列。新增后自动滚动/聚焦对应卡片；内容变高或删除后只让后续博文让位，照片不会随之自动移动。
- “图片”打开复用的上传面板，初始位置为当前作品窗口内的逻辑坐标。允许现有拖动、等比缩放、标注、删除和 ±25° 旋转；手势取消恢复开始前的值。
- “连线”进入显式模式：先选起点，再选终点，Escape 退出；保留现有允许类型，禁止自连、重复连接和博文—博文连接。草稿内不沿用 1.5 秒自动失效作为唯一操作途径，以便键盘和跨区域选择。
- 连线至少有一个端点属于当前作品。另一个端点可在本作品内，或来自公开 user_post/共享图片；不能借草稿创建完全属于外部内容的私密关系，也不能连接另一份私密草稿。
- 外部目标可直接从页面点选，也可通过有名称的目标选择器选取，解决被框覆盖、滚动后不可见和键盘操作问题。读取目标列表仍执行公开内容过滤，不能暴露他人草稿。
- 新建元素即确定归属；图片拖出边框只被裁切，拖到另一作品上也不转移归属。

### 3.4 My Draft、退出与删除

- My Draft 展示本人草稿列表，按最近修改时间和 ID 稳定排序/分页，显示首篇文章标题或“未命名草稿”、首张可见图片缩略图、更新时间。只有列表条目需要的摘要，不一次下载所有画布。
- 选择条目先完成当前草稿的保存流程，再切换；失败时保留原草稿和编辑缓冲，提供重试及显式放弃未保存改动的选择，不能默默跳走。
- 正常退出先冲刷防抖和上传队列，全部确认后关闭蒙版。刷新/关闭页面有未确认改动时使用浏览器离开提示；不能依赖 unload 请求承诺保存成功。
- 不自动删除空草稿；列表支持作者删除，操作前明确提示会删除该草稿内图文与连线。删除成功才移除条目。

### 3.5 首次发布与发布后编辑

- 发布前停止新增操作，等待文字、图片上传、连线和边框保存全部成功，执行完整校验，再提交发布请求；失败继续保留私密草稿。
- 允许纯图片或纯文字作品；至少有一项真实内容。存在空白文章时要求完善或删除，不能静默丢弃。所有文章使用既有标题 200 字符、正文 20000 字符上限及发布校验。
- 发布仍涵盖整组，包括被裁切部分；被裁切不算删除。feat-095 删除发布提示文案，编辑器不再渲染该说明或占位。
- 发布成功关闭草稿蒙版、从 My Draft 移除，并定位到时间线中的新作品；丢失响应后重试得到同一作品和首次发布时间。
- 公开展示保留组内裁切与布局，去掉 DRAFT、绿色编辑蒙版和手柄，保留轻微轮廓、作者/时间及可访问的作品操作入口。进入编辑时才显示边框和工具。
- 作者可编辑正文、通过手柄管理边框；整组删除的作者授权与 API 保留，原边框设置弹窗内的删除入口随弹窗一并移除，My Draft 的草稿删除入口保留。其他已登录用户可编辑图片和连线。正文在公开状态下仍点击“保存”才提交，避免把每个输入字符自动公开；图片/连线/边框在操作完成后保存，成功即公开，不要求第二次发布。
- 已发布作品后续新增正文必须完整填写后保存；组内新增文章可以有自己的创建/发布时间，但整组的首次发布时间不变。
- My Draft 的删除操作需要作者明确确认，删除所属内容及相关连线，不删除外部端点。协作者不能通过“删最后一张图”获得整组删除权限：最后一项被删后保留作品容器和“内容已清空”状态，整组删除 API 继续要求作者身份。
- 公开作品读取新版本即可看到更改；本期不承诺实时协同光标或逐帧广播。打开编辑时、页面恢复可见时、手动刷新时重新读取；可编辑作品面板在无本地未保存改动时每 5 秒回读，遇到冲突停止覆盖并提示。

## 4. 坐标、裁切、布局与连线绘制

将三种坐标明确分开：

| 层级 | 数据/职责 | 是否持久化 |
| --- | --- | --- |
| 作品内部场景 | 图片 x/y、尺寸、旋转；博文的固定列与自动纵向位置 | 图片几何与博文顺序持久化；博文高度由统一渲染器测量 |
| 作品裁切窗口 | viewportX/Y/Width/Height，决定内部场景可见部分 | 是，作者管理 |
| 页面与屏幕 | 私密编辑放置点 draftX/Y；发布后的时间线位置；查看比例 | 编辑放置点持久化且不出现在公共 DTO；公开位置由时间线推导，查看比例只留当前视图 |

从内部点 p 到屏幕点：`screen = containerOrigin + scale × (p - viewportOrigin)`；输入反算：`p = viewportOrigin + (screen - containerOrigin) / scale`。图片自身旋转的局部坐标换算在此基础上继续执行。

- 新作品固定 `layoutWidth = max(400, 初始框选宽度)`；博文卡片宽度采用 352，x 为 `max(24, layoutWidth / 2 - 32 - 352)`，首项 y=72，项间距 32。这些为初始布局常量，图像定位仍自由。不复用 Timeline 根据当前搜索作者集合计算左右侧的规则，以免同一作品因查看者或过滤条件而换位。
- 边框缩放不改变 layoutWidth 或卡片宽度，因此不会触发文字重新换行；正文内容变化、删除和字体就绪引起的真实高度变化，通过 ResizeObserver 更新后续博文位置与连线。
- 向左/上调整边界，同时改变窗口原点和外框屏幕原点，保持子元素场景坐标及当前显示比例。手势期间固定 scale，结束后也不因改边框自动缩放；首次打开或屏幕尺寸变化时重新适配。
- 默认查看比例为 `min(1, 可用宽度 / viewportWidth)`，适用于首次打开和屏幕尺寸变化。不再提供独立放大/缩小/平移视图；初始等比适配不改变内容裁切窗口。
- 工具栏、表单、焦点环和可交互手柄维持屏幕上的可用尺寸，不跟着作品缩成难以点击的小点。保留的正文及连线面板 portal 到 body，带焦点管理和关闭后焦点归还；普通页面不产生横向溢出。
- frame crop、视图缩放和图片 resize 是三个独立操作，分别测试，不能共用一个“宽高变化即重算内容”回调。

窗口容量契约：只保留前后端共用的 160×120 到 8192×8192 边界校验，不再计算全量元素的扩展候选窗口或等待扩展测量。博文真实尺寸观察仍用于自动排列和实时连线。

元素数量与窗口容量独立：300 篇博文的总高度为 `72 + Σ卡片高度 + 299×32`，仅起始偏移与间距已达 9640，必然超过 8192；两张远距图片也可能超宽。超出窗口的内容仍保留、可整组保存和发布；不提高窗口上限，不缩放/重排场景来强行容纳全部，不再通过目录承诺全量访问。

可见端点的统一几何契约：

- 图片以参与旋转的卡片矩形为语义区域，包含卡片内容/标注，不包含阴影、按钮或手柄；不做图片透明像素的逐点命中判断。显式固定 `transform-origin: center center`，从实时未旋转位置和宽高生成四角，绕卡片中心按当前角度旋转为凸四边形。博文使用当前未旋转卡片矩形。
- 锚点注册提供实时场景四角或可推导四角的位置/尺寸/角度，不能只返回旋转后的 DOMRect。使用当前拖动、旋转及 CSS 宽高预览值，不能仅取最后一次保存的 DTO；祖先平移/缩放通过同一坐标变换处理。
- 在统一、未缩放的场景坐标中，将元素多边形与所属作品裁切矩形求交；存在其它实际裁切容器时也转换到相同坐标并依次求交。仅正面积交集可作为连接区域；空集、点接触、边接触及退化顶点没有可见端点。浮点容差只消除计算噪声，使用同一逻辑坐标单位，不引入随屏幕缩放变化的最小可见尺寸。DOMRect/AABB 可作快速排除，不能作为最终相交判定。
- 连接点取实际交集凸多边形的面积质心，再映射到对应 SVG 坐标。不得取交集外包矩形中心。两端任一无可见交集时，不绘制该连接的线、钉子或透明命中路径；几何可见性不删除任何持久化数据。

连线按归属和显示范围分层：

1. 两端均在同一作品的线，使用上述实际交集和质心，在作品内部 SVG 绘制，并对线与钉子继续应用窗口裁切。图片中心被裁掉但仍有正面积可见部分时可连接；扩大窗口后重新计算锚点。
2. 跨作品/旧公开内容的线由页面级连线层绘制，对每个端点分别求其实际可见多边形及质心，再通过各自的场景/视图变换映射到同一页面 SVG。只有两端交集均有正面积且权限允许才绘制，不能因旋转后的包围盒占据空白处而画出线或钉子。
3. 外部端点因分页、搜索或未挂载而缺席时暂不绘制，不删除线、不虚构坐标，也不为绘图加载整站内容。回到包含目标的视图后恢复。
4. 发布后作品位置变化、页面滚动、视图缩放、图片旋转/大小变化、正文布局变化都重新测量锚点；一次 animation frame 合并测量，拖动中不依赖过期闭包。
5. 全局线不会把草稿边框内的所有对象自动当端点。连线数据、两端可见性和挂载状态均满足后才渲染；隐藏草稿时同时移除其私密连接图层。

## 5. 数据模型与增量迁移

以下是拟定字段契约，实施时使用严格 Prisma/TypeScript 类型。新增时间戳迁移，不修改已应用迁移。

### 5.1 BlogWork

| 字段 | 设计 |
| --- | --- |
| id | cuid 主键，作品跨草稿/发布保持稳定 |
| boardId | FK 到 AtlasBoard，服务端固定 home-board，不接受客户端自由指定 |
| ownerId | 非空 User FK；作者是私密权限和整组管理权限来源 |
| status | draft / published，只有发布服务允许 draft → published |
| publishedAt | nullable，草稿为 null；首次发布填入，之后不改 |
| revision | 非负整数，所有作品内容/边框写入的并发版本 |
| draftX / draftY | 私密编辑放置点，有限数值，只返回作者编辑 DTO |
| viewportX / viewportY | 内部裁切窗口原点，可为负值 |
| viewportWidth / viewportHeight | 正数且在输入预算范围内 |
| layoutWidth | 创建后固定，避免裁切驱动博文重排 |
| createdAt / updatedAt | 列表排序与审计时间；updatedAt 不参与公开时间线排序 |

索引：`(ownerId, status, updatedAt DESC, id DESC)`、`(status, publishedAt DESC, id DESC)`；为 board 归属约束提供 `(boardId, id)` 唯一键。CHECK 约束确保 draft 的 publishedAt 为 null、published 非 null，以及合法尺寸/版本。

owner 删除采用级联删除作品及其内容；上传清理账本不随作品删除消失，仍可回收对象。此规则不新增账号删除产品入口。

### 5.2 扩展已有内容实体

- **Post**：增加 nullable workId、nullable workOrder；publishedAt 改 nullable。旧记录保留原时间、slug、作者和正文，workId/workOrder 为 null。新增 `(workId, workOrder)` 唯一约束，保证组内添加顺序；workId 的删除策略为 Cascade。
- 新草稿文章立刻有 Post ID，slug 暂用服务器生成的 `draft-<opaque-id>` 保持现有非空唯一列；该临时 slug 不通过公共详情/API 暴露。正式发布时按标题使用现有 slug 分配规则替换，端点关系继续基于 ID。
- 草稿的标题/正文可以为空，但有相同长度上限；不在自动保存时破坏 Markdown 尾部空格。发布时使用现有完整 Zod 契约归一化并验证。agent_log 不允许关联 work，旧未分组 Post 必须继续有 publishedAt。
- **AtlasElement**：增加 nullable workId 和 nullable mediaAssetId。未分组旧内容保持 null；新作品内图片使用局部坐标。正文的 note anchor 与 Post 必须属于同一 work，且 postId 继续唯一。作者、workId、boardId 由服务层写入，不允许 PATCH 转移归属。
- **AtlasConnection**：增加 nullable workId，表示连线所属作品，独立于两端对象；增加 updatedAt 便于回读。草稿线即使连到公开对象，仍根据自身 work 状态保持私密。
- 作品关联与 board 一致性使用组合 FK 或等价数据库约束保证；Post anchor 的 work 关联一致性同样在数据库约束及领域写入中验证。旧 null 关联继续兼容。
- 新作品线使用不区分方向的端点对唯一约束：在 workId 非 null 的记录上对 `(boardId, LEAST(fromId,toId), GREATEST(fromId,toId))` 建唯一索引，保留旧有向唯一约束。迁移不合并或删除旧共享线；新入口同时检查两种方向并将冲突转成 409。
- work 删除级联其 Post、元素与所属线；元素删除级联所有以其为端点的线。跨作品关联不能级联删除另一作品或外部 Post。

### 5.3 BlogWorkMutation 与 BlogMediaAsset

**BlogWorkMutation** 保存变更幂等事实：actorId、mutationId、目标 workId、操作类型、规范化输入摘要、结果资源 ID、完成状态/时间；`(actorId, mutationId)` 唯一。同一键异载荷返回 409。只存恢复所需的标识与版本，不复制正文和图片字节。workId 为逻辑标识，不随作品删除级联丢失，用于阻止删除/创建响应重试引发复活；记录清理保留不少于 7 天。

**BlogMediaAsset** 仅治理本期新作品上传：id、storageKey 唯一、ownerId、可空 workId、uploadMutationId、contentType、size、status（pending/ready/cleanup）、expiresAt、清理尝试/下次重试时间、createdAt/updatedAt。work/owner 删除后账本可留存，元素通过唯一 mediaAssetId 引用；无可见元素引用的对象一律不能读取。原图片 URL 字段保留为展示 DTO 的兼容字段，不能由客户端直接指定存储 key 或他人资产 ID。

### 5.4 迁移和兼容执行顺序

1. 在真实临时 PostgreSQL 上验证新增表/nullable 字段/索引/约束；旧数据默认没有 work 关联，不自动创建分组，也不回写坐标。
2. 先覆盖所有公共读取过滤和旧写入口约束，再让任何 UI/API 创建草稿。服务端读取必须 fail closed；不能分批部署“已能写草稿但仍使用旧公开查询”的版本。
3. 旧 user_post 和 agent_log 的 nullable publishedAt 类型，在公共 DTO 构造层验证非空后收窄；不能以类型断言掩盖草稿泄漏或把 null 当当前时间。
4. 首页补 Post anchor 的现有并发删除/唯一约束保护继续保留；该补写只处理已发布的旧独立文章。作品内 anchor 随新增文章在事务中创建，不再由旧补写路径补成全局元素。
5. 迁移测试使用“上个迁移版本的旧记录 → 本次 migrate deploy → 查询/编辑”的真实路径，并验证可重复 deploy 不重复改动。
6. 生产切换采用停止旧 Web 写入窗口后迁移、切换新 Web/Worker，再恢复服务；旧版本不能在新草稿产生后继续服务，因为它没有新的过滤条件。含私密草稿的数据不能直接回滚到旧二进制；失败时保留新权限保护、前向修复或回滚至事前备份，不删除迁移掩盖状态。

## 6. 权限矩阵与读取封闭性

| 操作 | 草稿作者 | 其他已登录用户访问草稿 | 已发布作者 | 已发布其他用户 |
| --- | --- | --- | --- | --- |
| 读取作品/所属文字图片/线 | 允许 | 404 | 允许 | 允许 |
| My Draft 列表 | 仅本人 | 不返回他人条目/计数/预览 | 不包含已发布项 | 不包含他人草稿 |
| 新增/修改/删除正文 | 允许 | 404 | 允许 | 403 |
| 调整边框、删除整组 | 允许 | 404 | 允许 | 403 |
| 图片增删改 | 允许 | 404 | 允许 | 允许 |
| 连线增删改 | 允许，含合规外部目标 | 404 | 允许 | 允许 |
| 首次发布 | 允许 | 404 | 幂等返回既有发布事实 | 403 |
| 读取图片字节 | 对可访问且 ready 的引用允许 | 404 | 允许 | 允许 |

所有 API 先通过 [lib/auth.ts](../../lib/auth.ts) 的认证，再经过同域 Zod 校验和集中权限策略。未登录 API 返回 401，页面沿用登录跳转；他人私密资源与不存在资源一致返回 404，避免泄漏存在性。

建议统一策略函数：`canReadWork`、`assertWorkMutation`、`getPublishedPostWhere`、`getWorkElementWhere`、`getVisibleConnectionWhere`、`assertAssetRead`。读取与写入策略分开，不能把“可以看公开正文”复用为“可以改正文”。公开 DTO 不携带草稿放置坐标、私密草稿列表信息或内部清理状态。

必须逐一覆盖的入口：

- `/home` 的 SSR/RSC 初始数据、Blog 新 feed、搜索、分页和 My Draft。
- `/api/posts`、`/api/posts/:slug`、`/posts/:slug`、`/posts/edit/:slug` 与 Post Actions；公共文章入口只读已发布内容，自己的草稿也经专属作品接口读取。
- Home 旧元素、上传、连线入口与快照：只操作 workId=null 的旧共享对象；新作品 ID 不能借旧接口省略 expectedStatus/baseRevision。
- 旧 Atlas GET/PATCH/DELETE/清空/连线/drag 路径继续限定 atlas-global-board；新作品不读取旧 drag cache，不允许旧缓存写入影响 Home 作品。
- 图片字节入口：优先查 BlogMediaAsset 与其元素/作品；不存在账本时只兼容数据库中真实旧 Atlas/Home 图片引用，且按其 board/Post 可见性授权。不能退回“登录了就读取任意磁盘/OSS key”。

新作品跨组线必须同时满足：连线本身可见、两端可见、至少一端属于所属作品、外部端点已公开。连接不是移动权限，不能改变被连接对象。新作品的外部目标不包含房间私密 agent_log；旧照片—Agent log 连接保持既有房间过滤。

所有身份相关 API 成功和失败响应、图片字节响应都应用 `private, no-store` 和 `Vary: Cookie`，复用 [noStoreResponse](../../lib/api.ts)，避免不同账号复用缓存。前端状态以 currentUserId + workId 隔离；请求携带当前用户预期值并由服务端与会话核对，账号变化/401 时中止请求、清除私密编辑状态和对象 URL，迟到响应不能写入新账号界面。预期用户值只防串号，不替代服务端认证。

## 7. 自动保存、冲突与原子发布

### 7.1 写入协议

新作品变更均携带 `mutationId`、`baseRevision`、`expectedStatus`，外加 `X-Blog-Viewer-Id` 身份前置条件。服务端从 Session 得到 actor，绝不接受 ownerId/createdById 作为授权依据。

一次变更的顺序为：认证与输入校验 → 检查本人 mutationId 是否已有相同操作结果 → 事务内校验作品/资源权限及预期状态 → revision 条件更新 → 执行内容变更 → 写幂等结果 → 返回确认后的 revision。没有返回确认前，客户端不能展示“已保存”。同一 mutationId 的网络重试可以返回原提交事实，但不会用旧响应整体覆盖更新的客户端状态。明确收到未提交的 409 后，重读/rebase 属于新指令，使用新 mutationId；不能复用旧键提交不同 revision 或载荷。

- 事务使用 Prisma 共享客户端。涉及多个作品、外部端点删除或发布的事务使用 Serializable；涉及的作品按 ID 稳定顺序处理。P2034 等可重试数据库冲突只在完整新事务上有限重试，不在已失败事务中继续写。
- 每份作品使用一个客户端变更队列：文字建议 600ms 防抖；图片与边框移动只在完成手势后保存；上传完成、连线创建/删除也纳入队列状态。相邻同一资源的 PATCH 可以合并，创建/删除和不同资源的操作保持顺序。
- 草稿文本输入期间可继续编辑，队列保留最新值；旧响应只确认已发送的那一批字段，不回放整个快照覆盖后续输入。
- 版本不匹配返回 409 和可重读的资源版本。读取最新值后，只有服务器相应字段与本地基线相同的 PATCH 可自动重放一次；同字段冲突保留本地编辑缓冲，提示选择采用最新内容或重新提交自己的修改。不得无提示覆盖他人的编辑。
- `expectedStatus=draft` 的迟到操作在发布后返回状态冲突，不得自动改成公开写入重试。资源已删除则停止对应队列、清除相关选择与线，不因重试复活。
- 外部端点删除服务在同一事务内清理连线并推进受影响作品 revision。所有可能删除相关 Post/照片的旧入口也必须调用该服务；级联、连接创建并发时重新读取受影响集合并验证真实数据库结果。

### 7.2 保存状态与离开

| 状态 | 可观察行为 |
| --- | --- |
| clean | 所有变更已确认，显示“已自动保存”及最后确认时间 |
| dirty / saving | 本地变更、防抖、队列、上传任一未完成，显示“保存中”，禁用发布 |
| failed | 显示失败原因类别和重试操作，保留已成功的内容及本地缓冲 |
| conflict | 保留编辑缓冲，呈现冲突解决入口，禁止继续自动覆盖 |
| publishing | 暂停编辑和重复提交，显示“发布中” |
| auth-invalid | 停止私密请求与写入，清理当前用户内容并进入重新登录流程 |

关闭文字面板不等于退出草稿；退出、新建另一稿、切换列表条目和站内跳转统一走 flush/失败处理。刷新后恢复的是服务器最后成功状态，本期不新增 IndexedDB、本地正文备份或离线写入队列。

### 7.3 发布事务

1. 客户端等待队列与上传全部确认，取最新 revision，提交带幂等键的 publish。
2. 服务端核对 owner、draft 状态与 revision，检查无未完成上传，至少一项内容、全部文章有效、资产 ready、端点和归属合法。
3. 在一个事务中为所有草稿文章分配正式唯一 slug，填入同一首次发布时间/作者位置快照，将 BlogWork 改为 published、设置 publishedAt 并推进 revision，记录 publish 幂等结果。
4. 同名 slug 使用既有 5 次候选上限。任何 P2002 必须根据冲突目标判断是否是 slug；需要下一个候选时回滚并重跑整个发布事务，不能复用已经被 PostgreSQL 判失败的事务。组内多篇同标题也不能产生重复 slug。
5. 任何验证、数据库写入或唯一性处理失败，整组仍是草稿，不允许出现“文章已公开、图片还私密”的中间状态。对象存储不在事务内上传或复制，发布不改变图片 key。
6. 提交成功后再执行 revalidatePath/客户端回读。缓存失效或响应失败不能回滚数据库已经完成的发布；幂等重试与查询显示真实结果，首次发布时间保持不变。

## 8. API、服务与旧入口兼容

建议新增以下路由，JSON/路径/query/multipart 字段均通过 `lib/blog-work/schemas.ts` 校验；Route Handler 只做认证、解析、调用、错误映射和缓存控制。

| 路由 | 职责 |
| --- | --- |
| GET `/api/blog/works` | 本人草稿列表及摘要，按 updatedAt+id 游标分页 |
| POST `/api/blog/works` | 根据完成的框选创建空白草稿；服务端确定 owner、board、draft 状态 |
| GET `/api/blog/works/:workId` | 完整作品快照，含调用者可见的所属连接、revision 和能力字段 |
| PATCH `/api/blog/works/:workId` | 作者调整窗口；私密放置坐标仅草稿作者可写 |
| DELETE `/api/blog/works/:workId` | 作者删除整组；事务清理记录并登记资产回收 |
| POST `/api/blog/works/:workId/posts` | 新增文章；草稿可为空，公开作品必须完整 |
| PATCH/DELETE `/api/blog/works/:workId/posts/:postId` | 修改/删除所属文章，校验作者和 work 归属 |
| POST `/api/blog/works/:workId/uploads` | 校验并上传图片，返回已关联的元素及确认版本 |
| PATCH/DELETE `/api/blog/works/:workId/elements/:elementId` | 图片位置/尺寸/旋转/标注/删除；拒绝借此修改 note anchor |
| POST `/api/blog/works/:workId/connections` | 创建内外连接，至少一个端点属于当前作品 |
| PATCH/DELETE `/api/blog/works/:workId/connections/:connectionId` | 改端点/颜色或删除，重新校验两端与所属作品 |
| POST `/api/blog/works/:workId/publish` | 首次发布及幂等重试 |
| GET `/api/blog/feed` | 公共 Blog 混合条目列表/搜索/分页 |

所有新写操作返回可确认的 revision、mutationId 及本次变化结果。400 用于输入错误，401 登录失效，403 可见资源的无权操作，404 不可见/不存在，409 用于版本/状态/重复关系冲突；错误码使用稳定枚举，500 沿用通用内部错误和关联日志，不暴露 ORM/存储异常载荷。

服务拆分建议：`queries.ts`、`policy.ts`、`mutations.ts`、`publish.ts`、`assets.ts`、`schemas.ts`、`types.ts`、`geometry.ts`。共享事务接受 Prisma transaction client，使 Post、图片、连接、版本和幂等事实在同一提交边界中完成。

兼容规则：

- `/posts/:slug` 继续提供已发布单篇正文，作品内文章增加“返回所属作品”入口。草稿临时 slug 对公共详情/API 一律 404；作者在草稿面板内阅读。
- `/posts/edit/:slug` 对旧独立文章保持原编辑页；对作品内已发布文章转到作品的文字编辑面板。是否拥有正文始终由服务端校验。
- `createPost` Server Action 为 New Post 保留认证、标题/正文完整校验、唯一 slug、地点快照、错误反馈和既有结果形状，调用 `createStandalonePost` 发布 workId/workOrder 为空的独立文章；原详情、编辑与时间线分侧继续适用。旧 `POST /api/posts` 的现有兼容行为保留：调用事务服务创建已发布单文章作品与 anchor，不在本次导航恢复中改变该 API 契约。空间草稿依旧使用专属 API。
- 旧已发布文章的 PUT/DELETE 和 Actions 保留对外语义。属于作品时委托相同领域服务检查作者、更新作品 revision、处理 anchor/连接；旧接口没有版本参数时保留既有最后保存语义，但只能修改已发布内容。新的编辑器走带版本的新接口。
- Agent log 创建与投影继续使用原路径，workId=null，保持任务幂等键、房间可见性和发起者分侧；不为了 UI 发布流程而重写 Agent Runtime。
- 右键“添加图片”在未编辑作品时仍创建原共享照片；作品编辑模式下新增图片必须明确进入当前作品并展示该范围，不能因坐标落在框内而静默变成私密或公开。
- 原 Home/Atlas 图片尺寸、格式和旋转约束保留。原 home-board 的 300 元素限额只统计旧共享层；新作品按单作品最多 300 个元素、1000 条所属连接校验，包含被裁切内容，并在事务中执行计数，避免私密草稿消耗其它人的全局共享配额。

## 9. 时间线、搜索与分页

首页服务端与前端搜索统一调用 `queryBlogFeed`，避免 SSR 与搜索两套分组语义。返回 discriminated union：`{kind: post, post}` 或 `{kind: work, work}`。

- 旧独立 Post/agent_log 进入 post 分支；已发布 BlogWork 进入 work 分支。带 workId 的 Post 不再作为 Blog 独立条目，但既有 `/api/posts` 仍可按文章契约返回已发布子文章。
- 作品条目占一个完整行，在现有时间轴中心展示组内画布；旧独立文章的左右布局保持。移开现有父容器统一 max-w-3xl 限制，将其保留在旧文章行，作品行可用桌面较宽区域（建议最大 1440），按 D11 适配。
- 查询取最新页，界面仍按旧方向反向排列。不因为截图上新内容在上就改变既有时间线方向。
- 新 feed 游标为严格校验的 base64url `{v:1,publishedAt,kind,id}`，排序使用 `(publishedAt DESC, kind DESC, id DESC)`，字面顺序由常量固定。它与旧 `/api/posts` 的游标分开，不混用。
- 实现可对“旧独立 Post”和“已发布作品”各取 limit+1，经同一个复合排序合并后截取全局 limit；两边都按完整游标边界过滤。先确定本页 work，再读取其完整子项，禁止先分页子文章再临时分组。
- 搜索匹配旧 Post 标题/正文，或作品内任一已发布文章标题/正文、图片标注；作品命中一次就返回整个作品，并携带匹配元素 ID 供定位。不因只命中一篇而隐藏同组其它内容、重新排版或把子文章重复列出。
- 草稿只在 My Draft 中出现；普通 Blog 搜索即使由作者执行，也不混入私密稿。纯图片作品能正常进时间线，填写标注后可被搜索。
- Home 初始共享层快照排除所有 workId 非 null 的元素；作品层随当前 feed/主动打开的草稿按需读取。跨作品线只取与当前可见条目有关且通过权限过滤的记录；两端未挂载时遵守第 4 节显示规则。
- 保留现有搜索的请求取消、迟到响应隔离、失败时保留上一次结果、明确重试和空结果提示。成功发布/删除后回读条目并修正列表，避免仅靠乐观追加造成同一作品两份。

## 10. 图片字节、上传与回收

沿用 JPEG/PNG/WebP、5MB、字段先验证、字节魔数验证、服务端随机 key 和惰性加载 OSS SDK；不新增供应商。新作品图片通过现有受鉴权字节路由访问，不暴露可长期直连的 OSS URL。OSS 新对象使用私有访问配置，部署必须保证对象不能被匿名读取。

上传流程：

1. 认证、作品权限、revision/state、字段与文件校验通过后，创建带随机 key 的 pending 账本/上传幂等记录，推进并记录本次预留后的 revision，计入待完成上传。上传正在进行时不能发布该作品；最终关联以预留后的版本为基线，而不是复用上传前的旧版本。
2. 在事务外写入对象，使用服务端判定的 contentType；成功后回到事务，再次验证身份对应权限、作品状态/版本与账本状态，创建 photo、绑定资产并将账本置 ready。
3. 任何数据库失败、版本冲突、作品删除或上传取消都不能把对象挂到其它作品；登记 cleanup 并尝试删除。重试同一上传键不能重复新增图片；客户端只有拿到 ready 的已关联元素才算保存成功。已确认清理/冲突的上传需重新发起时使用新 mutationId 和 key；尚不确定结果的网络重试先查询/重放原幂等事实。
4. pending 请求有明确超时与过期时间，建议 24 小时回收未完成记录；过期账本不再允许迟到完成。若存储请求迟到写入，完成分支仍须清理，回收账本保留至确认对象不存在，不能先删账本再依赖内存善后。

读取流程：先验证 DB 中 ready 资产与有效元素引用，再验证作品可见性，最后读取存储。pending、cleanup、无引用、他人草稿以及路径畸形均拒绝。公共作品发布不复制图片或换 key，仅改变受控读取权限。

删除流程：在数据库事务中删除元素/作品、级联连线并记录 cleanup；提交后清理 blob。存储暂时失败不复活已删除内容，也不阻断已成功的数据库删除；保留可重试事实。GC 再次删除前检查没有有效引用，且 key 属于该账本，不能遍历删除其它存储对象。

具体回收路径：

- `lib/blog-work/assets.ts` 提供有界批次处理，删除/上传失败后立即尝试；只有 ENOENT/NoSuchKey 等“已不存在”算幂等成功，其它错误留待重试。调整存储适配层的 delete 错误契约，新服务处理真实错误，原调用者的显式 best-effort 行为仍可保留。
- 新增 `scripts/cleanup-blog-assets.ts` 与 `npm run blog:assets:cleanup`，支持 dry-run、批次大小和重试结果统计，供失败恢复及定期运维执行。不在本期新建 Agent 定时任务或常驻清理服务；未执行回收时可能占用额外磁盘，但不可访问性由数据库即时保证。
- 为 Compose 提供明确可执行路径：将该脚本复制进 worker-runner，复用其 Node/tsx、环境与上传目录，运行 `docker compose exec -T agent-worker npm run blog:assets:cleanup -- --limit=100`。这不是 Agent 工具调用，也不改变 Worker 消费循环；镜像打包与实际执行需用隔离 Compose 验证。
- 旧图片继续通过真实旧记录授权，不批量移动或删除历史 blob；本期 GC 只处理有新账本的对象。用户原有参考 PNG 不属于上传清理范围。

### 13.2 必须跑通的生产浏览器旅程

1. 作者右键新增 → 框选 → 两篇博文和两张照片 → 图片移动/缩放/旋转 → 内部与外部连线 → 等待“已自动保存” → 退出 → 刷新 → My Draft 恢复，内容与坐标一致。
2. 草稿框覆盖现有公开文章/图片，移动边界和发布均不改变旧内容的归属；框外图片只是裁切，扩大恢复原尺寸/坐标；正文变长只让后续正文让位。
3. 第二账号在发布前通过页面、搜索、详情、API、图片 URL、连接和旧 Home/Atlas API 均不能读取/修改草稿。响应载荷也不得包含私密标题、标注、key 或连接关系。
4. 作者发布后第二账号看到一组作品、原构图及公开外部线；第二账号能改图/线，不能改正文、边框、删除整组或触发首次发布。
5. 故意延迟/失败保存和上传，发布保持不可用；重试不重复照片/线。发布响应丢失后重试只产生一次发布；另一标签页的迟到 draft PATCH 不能覆盖公开内容。
6. 同账号两个标签页编辑同一作品，制造同字段冲突，验证提示、本地缓冲保留和重新选择；两个不同用户同时编辑公开媒体，验证不因整份快照回写丢失对方内容。
7. 在 375/390px 触摸视口和桌面视口检查：默认等比适配、点击博文读文/编辑、键盘控件、正文表单不缩小、坐标逆变换准确、横竖屏切换不改保存数据、页面没有意外水平滚动。
8. 作者通过 My Draft 删除草稿或通过既有 API 删除已发布作品，确认所属图文/线消失、外部内容仍在、图片请求拒绝；协作者删除最后一项内容后容器仍由作者管理。
9. 退出或切换账号期间迟到响应不能重新显示草稿；图片缓存不能让另一账号读取先前草稿字节。测试使用隔离 BrowserContext/独立账号，并注意现有单 Session 策略。
10. New Post 与 /posts/new 恢复原独立表单并可发布到文章详情；验证新 Post 的 workId 为空且未创建 BlogWork，独立文章编辑/详情及时间线仍可用。New Draft 链接不存在，右键框选/取消/键盘默认区域及 My Draft 空态引导可用；旧共享照片和 Agent log 保持原权限与展示，搜索失败/重试及新旧分页稳定。
11. 使用隔离数据建立 300 篇合法博文以及另一份仅两张远距图片的作品，保留窗口外数据；既有博文深链可编辑末项而不改裁切范围。键盘手柄允许到达 8192，继续增大不能越界；后端继续拒绝 8193。合法作品仍可正常保存/发布。新增桌面 479/480/481/240px 与最小窗口回归，验证单层蒙版、底部仅三个工具按钮、旧入口和提示消失、工具栏随边框移动。
12. 640×640 图片绕中心旋转 25°，裁切窗口放在旋转后 AABB 的右上角、宽160高120：其 AABB 交集面积为19200但真实多边形交集为空，确认没有该连接的线、钉子或透明点击路径。扩大窗口到确有正面积交集后恢复连线，锚点位于实际交集内；同时覆盖负角度、中心已裁掉但仍有局部可见、触摸 resize/旋转预览和不同视图缩放。
13. feat-097：真实鼠标连续平移四边可拖动区，确认图文/蒙版/状态/工具栏同步、手势中零写入、松手只保存 draftX/draftY；交替平移和缩放保持两种坐标语义。覆盖 Escape、pointercancel、丢失捕获、连续手势中延迟响应与失败幂等重试、退出及刷新恢复、390px 比例、Tab/方向键/Shift 步长、图片与正文操作不抢占，发布后不再出现平移入口。

浏览器几何用例等待 PageTransition/scroll-reveal 真正完成后测量，不能只固定 sleep。保留 feat-090 的真实连续鼠标/触摸旋转回归、菜单边缘/滚动后定位、Home 粘性导航回归。断言实际图片、线与焦点可见和操作结果；HTTP 成功不能代替画布显示验收。
